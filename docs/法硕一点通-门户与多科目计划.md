## 一、目标结构

一个站点、一个门户、五门独立科目包。**不拆成五个仓库、五个域名**——登录态、会员、邀请链接都按域名隔离，分域会让用户换科目时重新登录，也会让已发出的邀请链接失效。

```
/                门户：选科目 + 账号/会员状态（不含任何教学内容）
/fz/             中国法制史（已上线）
/mf/             民法（待接入）
/xf/             刑法（待接入）
/xfa/            宪法（待接入）
/fl/             法理学（待接入）
```

- 每门课一套独立的 `index.html / app.html / sw.js / version.json`，各自的版本号、CHANGELOG、离线缓存、发版记录。
- 一门课重新发布，不会让另一门课重下 6.5 MB，也不会互相牵连。
- 门户只读一份 `subjects.json`（上线状态、考点数、图标），据此渲染卡片。
- 共用：Supabase 的账号、会员、卡密、邀请、免费额度、设备限制，以及一个后台。
- 独立：每门课的模板、数据、术语与教辅、科目色与印章字。

地址用路径式 `/fz/`，而不是 `/?s=fz`。旧的 `/?s=fz` 保留并自动跳转。

## 四、开工前要谁做什么

### 1) 只有用户能拍板的

- 总名最终是「法硕一点通」还是别的（所有文案跟它走）。
- 仓库与站点地址是否改：建议**不改仓库名**，继续 `kkdlm.github.io/fazhishi`，根目录变门户，`/fz/` 是法制史。改仓库名会让 Pages 地址变，老链接靠跳转不稳。
- 对外口径：「五门课，一个账号」还是「五门课陆续上线」。

### 2) 只有用户能在第三方后台做的

- Supabase → Authentication → Emails / SMTP：改 `Sender name`（默认 `Supabase`）。**发件邮箱域名改不了**，免费项目用共享发件域；要自己的地址需配自有 SMTP（企业邮 / Resend 等）。
- Supabase 邮件模板：注册确认、登录验证码两封邮件的标题与正文里的产品名要换成总名（模板文案由我提供，用户粘贴）。
- 若改仓库名：GitHub 仓库设置 + Pages 设置。
- 已经发到别处的链接/二维码/群公告（只有用户知道有哪些）。

### 3) 我做的

门户上线、法制史迁 `/fz/`、旧链接 `/?s=fz` 自动跳、老 Service Worker 退场、全站文案替换（App/后台/邮件模板）、按科目拆发版、文档。

### 4) 迁移后用户验收（约 5 分钟）

1. 旧链接打开 → 门户，不 404。
2. 门户进法制史 → 进度/收藏/笔记都在（旧数据已迁移）。
3. 收一封验证码邮件 → 发件人名是总名。
4. 收一张邀请链接 → 点开注册 → 双方天数到账。
5. 手机桌面快捷方式（若加过）→ 名字变了要删掉重加。

## 五、迁移时必须处理的坑

1. **老 Service Worker**：用户手机里缓存的根目录 `sw.js` 会继续吐旧的 `app.html`。迁移时根 SW 要改成只服务门户，并主动注销/接管旧缓存，否则老用户打开门户看到的是法制史页面。
2. **localStorage 按路径共享**：同域下 `/`、`/fz/` 的 localStorage 是同一个，所以登录态天然互通；但也意味着 `lastsubj` 等全局键不要被科目命名空间误搬（已在 4.1.0 里用 `GLOBAL` 白名单处理）。
3. **邀请码 / 卡密前缀不改**：`FZ` 与 `FZ-90` 已经发出去了，改前缀会让存量卡密核销失败、邀请码失效。
4. **进度兼容**：4.0.0 版本不带 `subject`，靠列默认值 `fz` 写入；新版本读 `subject=eq.fz`，两者共存不冲突。
5. **不要两件事一起做**：先迁结构（不变名），验证旧链接/进度/邮件都正常，再统一改名。
