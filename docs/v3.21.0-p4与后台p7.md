## v3.21.0-p4（2026-11-21）卡密兑换「偶尔没反应」

- 症状：用户点「兑换」偶尔完全无反馈（有时成功、有时点了像没点）。
- 根因：`sbReq` 没有超时，弱网/切后台时 `fetch` 一直挂起 → `await rpc('redeem_card')` 永不返回，界面既无 toast 也无按钮态；同时 `redeemCard()` 没有 busy 态与防重入，连点会同时发多个核销请求。
- 改法（`build/app_fz.html`）：
  1. `sbReq` 统一超时：`AbortController` + `opt.timeout||20000`，中止时抛 `Error('请求超时')` 且 `code='TIMEOUT'`（`finally` 清 timer，401 自愈重试不受影响）。
  2. `redeemCard(btn)` 重写：`REDEEM_BUSY` 防重入（重复点击提示「上一个兑换还在核销」）；`busyOn(btn,'核销中…')` 期间按钮禁用；返回时间兼容 `timestamptz 字符串 / 数组 / jsonb{ok,until}` 三种形状；成功即时 `renderAcct()` + `loadFreeState()` 并 0.5s 后关层。
  3. 失败文案按原因分开：`TIMEOUT`→「网络太慢，别急着重兑，重进我的看会员到没到」；卡密无效/已被使用；登录已过期（明确「卡密不会被扣」）；联网才能兑换；服务端未建兑换函数。
  4. 三处入口（会员弹层、设置页卡密块）改 `redeemCard(this)`，输入框回车直接兑换。
  5. CHANGELOG 顶部新增 p4 五条；`const PATCH='4'`。
- 验收：`build/verify_fz.py` 320/390/430 溢出 0、pageerror 0、抽背 215 无空；`/tmp/verify_redeem.py` 场景 A 正常兑换（toast+VIP）/ B jsonb 形状 / C 卡密无效且按钮恢复 / D 连点只放一个请求 / E 26s 挂起 → 20s 触发超时文案。
- 发布：`SRC=nVkuJLHE1D`（壳 `3.21.0-p4`，18,968 B）、`APPSRC=YsBYvSOgBV`（正文 6,519,072 B）、`SWURL=wWgFBRPNkr`（`app-3.21.0-p4`）、`version.json` patch 4 / s=6519072。
