# v4.0.0 邀请链接 + 版本号归位（2026-11-21）

目标：把邀请从“对方手动填 6 位码”改成“直接分享链接，对方点开 → 注册 → 登录，自动算邀请”。同时把版本号排法改回规范。

## 邀请链路

1. 邀请人在「我的 → 邀请有礼」点「复制邀请链接」，得到 `https://kkdlm.github.io/fazhishi/?inv=FZxxxxxx`（邀请码仍为 FZ + 6 位，不带任何个人信息）。
2. 对方点开：壳（`index.html`）从 `location.search` 读出 `inv`，校验 `^FZ[A-Z0-9]{6}$`，挂载正文时注入 `window.__FZ_INV="FZxxxxxx"`（正文跑在 blob iframe 里读不到地址栏 query，只能由壳送进去）。
3. 正文启动 `captureInvite()` → `INV_CODE`，并写 `localStorage['fzs2027.v1:pinv']`（未登录先存着）。
4. 未登录：登录墙新增提示条「你点开的是邀请链接：注册并登录后自动 +N 天会员，不用再填邀请码」；注册页的邀请码输入框自动带上该码。
5. 登录 / 注册成功：`afterLogin()` 里既有的 `claimPendingInvite()` 自动调 `rpc claim_invite`，双方按 `app_config` 加天数，toast「邀请成功：你 +3 天，邀请人 +7 天」。
6. 已登录且带码：启动后 700ms 自动认领，无需手动操作。

## 边界

- 手填码的老入口保留（「也可手填别人的邀请码」）。
- 每个账号终身只能被邀请一次；已用过的账号再点别人链接只提示一次，之后本地标记不再重复。
- 服务端未改 SQL：沿用 `docs/vip_cards.sql` 的 `claim_invite(p_code)`。
- 链接只携带 6 位码，不含邀请人身份信息。

## 验收（本地 `127.0.0.1:8811/shell.html?inv=FZD9CB5B` + mock Supabase）

- 壳注入 `window.__FZ_INV=FZD9CB5B`；正文 `INV_CODE=FZD9CB5B`、`pinv=FZD9CB5B`。
- 未登录：登录墙可见且提示条显示「注册并登录后自动 +3 天」；点「注册新账号」后邀请码输入框预填 `FZD9CB5B`。
- 注入登录态后重载：登录墙消失，`claim_invite` 调 1 次且 `p_code=FZD9CB5B`，toast「邀请成功：你 +3 天，邀请人 +7 天」，`isVip()=true`。
- `pageerror 0`；`build/verify_fz.py` 320/390/430 溢出 0、抽背 215 无空。

## 版本号归位

- 原计划排 `3.22.0`，已越界（次版本只能 0–9）。按规则 `3.9.9` 之后进位 `4.0.0`，本版改为 **4.0.0 / 补丁 0**。
- `release.yml` 第一步新增格式校验：`^[0-9]\.[0-9]\.[0-9]$` 与 `^[0-9]$`，越界版本直接失败。规则详见 `docs/版本号规则.md`。
