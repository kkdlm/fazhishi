## 1.2.0.7 上线顺序（以后照这个来）

1. `docs/lottery.sql` → `db.yml` 全量重跑，执行完再放前端，否则 `lottery_status` 缺字段、卡片显示 0 次。
2. 四件上传 CDN → `release.yml` env 六项（`VER`/`APPVER`/`SRC` 壳/`APPSRC` 正文/`SWURL`/`ADMSRC`）换成新地址。
3. 壳 `index.html` 里 `VER` 与 `VERB` 必须同时改（漏 `VERB` 会让 release 静默 `exit 0`）。
4. `sw.js` 的 `CACHE` 跟着版本走，否则用户端一直用旧缓存。
5. 跑完轮询 `version.json`，再核三处：壳 `VER/VERB`、`sw.js` 的 `CACHE`、`admin/index.html` 字节数。

## 已知限制

- `release.yml` 本身被改的这次 push **不会**触发它自己（GitHub 限制：改 workflow 文件的那次提交不启动该 workflow）。改完要再推一个普通文件、或手动 `workflow_dispatch` 一次，才能真正发布。旧版记录里的「改完就自动发」只对非 workflow 文件成立。
- `raw.githubusercontent.com` 缓存落后，核对仓库内容一律以 GitHub API 为准。
