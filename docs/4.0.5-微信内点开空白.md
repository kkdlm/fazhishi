# 微信 / QQ 内置浏览器点开链接一片空白（4.0.5 补丁 6）

## 现象
从聊天里点开分享链接（`…/fazhishi/?inv=FZxxxxxx`），启动页走完、进度到 100%，然后
整屏只剩底色、没有任何内容；没有报错提示，也没有「重新加载」。

## 根因
正文（6.5MB 的 app.html）不是直接打开，而是由外壳挂在一个 **`blob:` 地址的 iframe** 里跑：

```js
var url = URL.createObjectURL(new Blob([html], {type:'text/html;charset=utf-8'}));
fr.src = url;
```

微信 / QQ 内置浏览器（X5 内核）会拦这种装载方式，iframe 里是空文档。而旧壳在 8 秒后
**无条件**把 `mounted` 置为 true：

```js
setTimeout(function(){ if(!mounted){ mounted=true; } }, 8000);   // 假装成功
```

于是启动页正常收尾、iframe 仍是空的 —— 表现就是「加载完成，一片空白」。

## 修法（`build/publish/shell.html`）
1. 挂载后每 120ms 检查 iframe 里到底有没有东西（`contentDocument.body` 的子节点或文字量）。
2. 2.6 秒还是空的 → 不再用 blob，直接把这个 iframe 的文档写出来：
   `d.open(); d.write(html); d.close();`（`about:blank` 与父页同源，X5 认；`<base href>` 保证资源路径不错）。
3. 再 2.6 秒还空 → 显示启动卡片「这个浏览器拦住了页面装载…点右上角 ··· 选『在浏览器中打开』」，不再假装成功。
4. 首次下载路径与「本机已有正文 → 秒开」路径共用同一套 `loadInto()`，所以两条路都有兜底。

## 顺带修的一致性问题
正文里的 `const PATCH` 与线上 `version.json` 的 `patch` 必须同一个值。
不一致时正文会一直弹「v4.0.5 有补丁 N，现在更新吗？」，点了又没内容变。本次把两边都定为补丁 6。

## 验证（Playwright，390×844）
- 正常路径：iframe 为 `blob:…`，body 12 个子节点 / 944 字；二次打开走本机缓存同样正常。
- 模拟被拦：把 `URL.createObjectURL` 换成无效地址后，iframe 变成 `about:blank`，内容同样是 12 子节点 / 944 字，
  登录墙与「你点开的是邀请链接 · 注册并登录后自动 +3 天会员」提示条正常显示。
- `pageerror 0`。

## 用户侧生效方式
外壳被 Service Worker 缓存优先返回，所以已装过旧壳的手机要**重开一两次**（或点右上角 ··· 刷新）才换成新壳；
新壳一旦落地，后续打开都是本机秒开。
