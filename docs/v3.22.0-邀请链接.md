# v3.22.0 邀请链接（2026-11-21）

目标：把邀请从“对方手动填 6 位码”改成“直接分享链接，对方点开→注册→登录，自动算邀请”。

## 链路

1. 邀请人「我的 → 邀请有礼」点「复制邀请链接」得到 `https://kkdlm.github.io/fazhishi/?inv=FZxxxxxx`（邀请码仍为 FZ + 6 位，不带任何个人信息）。
2. 对方点开链接：壳（`index.html`）从 `location.search` 读出 `inv`，校验 `^FZ[A-Z0-9]{6}$`，挂载正文时注入 `window.__FZ_INV="FZxxxxxx"`（正文跑在 blob iframe 里，读不到地址栏 query，所以只能由壳送进去）。
3. 正文启动时 `captureInvite()` → `INV_CODE`，并写入 `localStorage['fzs2027.v1:pinv']`（未登录先存着）。
4. 未登录：登录墙新增提示条「你点开的是邀请链接：注册并登录后自动 +N 天会员，不用再填邀请码」；注册页的邀请码输入框自动带上该码。
5. 登录/注册成功：`afterLogin()` 内既有的 `claimPendingInvite()` 自动调 `rpc claim_invite`，双方按 `app_config` 加天数，toast 显示「邀请成功：你 +3 天，邀请人 +7 天」。
6. 已登录且带码：启动后 700ms 自动认领（不用手动操作）。

## 兼容与边界

- 手填邀请码的老入口保留（「也可手填别人的邀请码」）。
- 每个账号终身只能被邀请一次：已用过邀请码的账号再点别人的链接，只提示一次「这个账号已经用过邀请码了」，之后本地标记不再重复。
- 服务端无需改 SQL：沿用 `docs/vip_cards.sql` 里的 `claim_invite(p_code)`（幂等由 `referrals` 唯一性保证）。
- 链接不携带邀请人身份信息，只有 6 位码；码失效/未生成时提示刷新。
