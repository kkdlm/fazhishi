# 4.0.3 操作日志：谁能看到什么

## 一句话
只记「做了什么」（登录、兑换、换设备、邀请这类操作），不记「学了什么」（背到哪、收藏、笔记正文）。

## 用户端（App 里）
- 入口：`我的 → 操作记录`（一张卡，右侧 `>`）
- 内容：按日期分组的时间线，可筛 全部 / 登录 / 兑换 / 会员 / 设备 / 邀请 / 账号
- 只出可见级别 `self` 的记录，由服务端 `my_logs()` 过滤，前端拿不到 `admin` 级别的数据
- 每次 25 条，底部「看更早的记录」翻页

## 后台（`/admin/` → 日志）
- 「用户操作」：所有人的 `activity_log`，可按邮箱 / uid、按动作筛
- 「后台动作」：管理员自己做的事，来自 `audit_log`（加会员、封禁、清数据等）
- 列表用 `.lg-item` 自定义行，手机端不会裂成无表头的卡片

## 数据侧（`docs/vip_cards_v430.sql` 为唯一权威版本）
| 对象 | 作用 |
|---|---|
| `activity_log` 表 | id / uid / action / target / detail(jsonb) / vis / created_at，开启 RLS，不开放直读写 |
| `log_meta(p_act)` | 动作字典：中文名 + 可见级别 + 允许保留的 detail 字段白名单 |
| `log_activity(...)` | 写入；未登录不写，未登记动作丢弃，同动作 60 秒最多 12 条，detail 按白名单过滤 |
| `my_logs(...)` | 用户读自己的，只出 vis=self |
| `admin_logs(...)` | 管理员读全部，合并 activity_log 与 audit_log，`is_admin()` 守卫 |
| `admin_log_stat(...)` | 按动作统计最近 N 天（后台 KPI 备用） |

## 隐私边界（已落实在服务端，不是前端藏起来）
- 不记：学习进度、章节停留、笔记正文、收藏内容、IP、完整卡密、验证码
- 卡密只留后 4 位；设备只留尾号；邀请只留邀请码
- 未登录的操作一条都不写
- 日志写入失败静默，不影响任何主流程

## 排障记录（重要）
`log_meta` 最初用 `values (...)` 列表 + `array[]::text[]` 写法，在项目里经 Management API 执行一直失败，
而 `pglast` 语法校验是通过的（说明是语义层问题）。改为 `case ... end` 逐项返回 + `'{...}'::text[]` 字面量后执行成功。
另外 `coalesce(public.log_meta(x), ...)` 不能把「返回表」的函数当标量用，必须写成
`coalesce((select m1.label from public.log_meta(x) as m1 limit 1), x)`。
以后不要再改回 `values` 写法。

## 验证（数据库真的存在，不是纸面方案）
```
POST /rest/v1/rpc/log_meta    {"p_act":"login"}   -> 200 [{"label":"登录","vis":"self","keys":["method","device"]}]
POST /rest/v1/rpc/my_logs     {}                  -> 400 {"message":"需要登录"}
POST /rest/v1/rpc/admin_logs  {}                  -> 400 {"message":"需要管理员权限"}
POST /rest/v1/rpc/log_activity {}                 -> 204（未登录静默不写）
migration_probe 中 id=7/8/9/10/11 全部存在
```

## 4.0.4 补丁（同一功能的两处整理）
- 「我的 → 操作记录」右侧从文字「时间线」改成统一的 `›`，点整行都能进
- 类别筛选从 flex 自然换行改成固定四列（4+3），不再出现「账号」单独占一行
